# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`rNDC.Shiny` (Apache-2.0, maintained for LTER-LIFE; the GitHub repository is `LTER-LIFE/rNDC-Shiny`) is an R package with a Shiny GUI to LTER-LIFE's **NatureDataCube**. It is built on the [`rNDC`](https://github.com/LTER-LIFE/rNDC) package, currently from its `texel26` branch (`Remotes:` in `DESCRIPTION`), version 0.5 or later (`Imports: rNDC (>= 0.5)`: `ndc_with_progress()`, the exported defaults, `ndc_get(all_pages = TRUE)`, `adc_get_all()`, `get_ndvi_stats()` and the `ndc_*_years()` functions): prefer exported `rNDC::` functions over re-implementing requests here, and put generic helpers that other rNDC users would want in rNDC itself. Unqualified calls to imported packages must be listed as imports in `R/rNDC.Shiny-package.R` (`@import shiny`, specific `@importFrom` for the rest, to avoid masking); otherwise use `pkg::fn`. `DESCRIPTION` `Imports` lists the packages.

## Commands

Run R through the conda env: `conda run -n base_r Rscript -e '...'`. It has all dependencies, `devtools`, `roxygen2` and `webmockr`, and `rNDC` installed from `LTER-LIFE/rNDC@texel26`. Credentials for live runs are in `~/.Renviron`.

- Load during development: `devtools::load_all()`. Run the app: `NDC_TOKEN=... conda run -n base_r Rscript -e 'devtools::load_all(); ndc_gui(port = 3838, launch.browser = FALSE)'` (only `NDC_TOKEN` is required; dummy values are enough to check that the app starts and serves, but data requests then fail).
- Run all tests: `devtools::test()`; a single file: `devtools::test(filter = "retrieval")` (matches `tests/testthat/test-<filter>.R`). The tests are offline: HTTP is stubbed at transport level with `webmockr` (httr adapter; rstac and httr both go through httr). `tests/testthat/helper-fixtures.R` has `local_stac_api()` (stub STAC API at `https://example.org/api/`, with result pages and an optional error status), `adc_re()` + `geojson_features()` for AgroDataCube stubs, `request_uris()` / `last_request_body()` to inspect the requests, and `selected_polygon()`.
- Regenerate docs and `NAMESPACE`: `roxygen2::roxygenise()`. `NAMESPACE` and `man/` are **generated**; never edit them by hand. Imports are declared as tags in `R/rNDC.Shiny-package.R`, and every exported function needs `@export` plus a roxygen block.
- Full check: `R CMD build .` in a scratch directory, then `R CMD check --no-manual rNDC.Shiny_*.tar.gz`. It must stay free of errors, warnings and notes (CI uses `error-on: "warning"`).
- Live API tests (`tests/testthat/test-live.R`) are skipped unless `RNDC_LIVE_TESTS=true` (plus both tokens): `RNDC_LIVE_TESTS=true conda run -n base_r Rscript -e 'devtools::test(filter = "live")'`.
- Update rNDC to the latest `texel26`: `conda run -n base_r Rscript -e 'remotes::install_github("LTER-LIFE/rNDC", ref = "texel26", upgrade = "never")'`. Check `packageDescription("rNDC")$RemoteSha` when behaviour differs from what the rNDC source says.
- Container: `docker compose up --build` (or `podman compose`), reading `.env` (copy `.env.example`). The image installs rNDC from GitHub (`RNDC_REF`, default `texel26`), the other dependencies from `DESCRIPTION` (`remotes::install_deps()`, incl. `Remotes:`), then this package, and runs `rNDC.Shiny::ndc_gui(host = '0.0.0.0', port = 3838)`; the app is served at `http://localhost:3838/` (`SHINY_APP_BASE_URL` does not create a route, it only sets Shiny's `appBaseUrl` behind a reverse proxy). Docker is not available in the dev environment: the image is built by the `docker-build` workflow only. The build can use a GitHub token against the rate limit of the GitHub API (not kept in the image): `docker build --secret id=github_pat,env=GITHUB_PAT .`. The `docker-build` workflow builds the image with `GITHUB_TOKEN`, loads the package in it, runs a job in a fresh background process of the image, starts the container and checks that the page and the logo are served.
- CI (`.github/workflows/`): `R-CMD-check.yaml` runs the offline check on push/PR; `live-checks.yaml` runs the live tests weekly (default branch) or on manual dispatch, using the `NDC_TOKEN`/`ADC_TOKEN` repository secrets; `docker-build.yaml` builds the image (no push) when the Docker files or the package change. Repo: https://github.com/LTER-LIFE/rNDC-Shiny.
- Credentials come from env vars: `NDC_TOKEN` (NatureDataCube STAC API, also the default `token` of `rNDC::ndc_get()`, land use and nitrogen functions; **required**) and `ADC_TOKEN` (AgroDataCube: Fields, AHN, Soil map, Weather; **optional**, those datasets are disabled without it). Never write tokens to the repo or to outputs.

## Architecture

Code lives in flat `R/*.R` files:

1. **Launchers** (`ndc_gui.R`, `ndc_app.R`, the only exports): `ndc_gui()` runs `shiny::runApp(ndc_app(), ...)` and returns what `stopApp()` is given (the "Return data to R" button, shown only when `interactive()`); `ndc_app()` registers the `ndc-www` resource path (logo, from `inst/app/www`) and returns `shinyApp(app_ui(), app_server)`. `ndc_setup()` (internal, called by `ndc_app()`) stops without `NDC_TOKEN`, warns without `ADC_TOKEN` and sets `shiny.appBaseUrl` from `SHINY_APP_BASE_URL`. `inst/app/app.R` is a one-line entry point (`rNDC.Shiny::ndc_app()`) for Shiny Server.
2. **UI and server** (`app_ui.R`, `app_server.R`, `server_*.R`): `app_ui()` returns the page (CSS/JS inline, with plain input ids: no module namespaces). `app_server()` creates the shared `state` (`create_state()` in `server_state.R`: the reactiveVals for the drawn/selected/project/uploaded polygons, the `overview`, the download messages and the tokens) and the map `helpers` (`create_map_helpers()`: `update_selected_highlights()`, `clear_map_polygons()`, ...), and calls one function per area, each registering its observers and outputs and unpacking the state it needs at its top: `server_dataset()` (dataset settings, availability hint, adding to the overview; returns `build_controls_for()`), `server_projects()` (LTER/SNL layers), `server_map()` (clicks, drawing), `server_upload()`, `server_overview()`, `server_download()` (returns `retrieve_and_save()`) and `server_help()`. `app_server()` also keeps the state and those two functions by name in its own environment, which is how the tests reach them. The `overview` reactiveVal is the "shopping cart" (one row per dataset x polygon x year/dates, with the polygon `sf` in a list column). `retrieve_and_save()` loops over the rows with `retrieve_row()` (see 3), collects the data, the `download_summary.csv` manifest and the messages, writes the manifest into a unique temp folder, zips it with `zip_export()` and removes the folder. It backs both "Download" (zip) and "Return data to R" (`stopApp(list(datasets, overview, messages, summary, ...))`); per-dataset messages ("Retrieved: ...", "Failed: ... - reason") are shown in the messages panel. To add a piece of server logic, put it in the `server_*.R` of its area (or a new one, called from `app_server()`); share state through `state`, and functions used by several areas through `helpers`.
3. **Retrieval** (`retrieval.R`, no Shiny dependencies): `retrieve_row(row, index, workdir, ndc_token, adc_token)` handles one overview row. `retrieve_dataset()` dispatches to one function per dataset (`retrieve_agricultural_fields()`, `retrieve_weather()`, `retrieve_nitrogen()`, `retrieve_ndvi_rasters()`, ...), each returning an *outcome*: `outcome_data()` (the data, its name, file extension, messages and optional writer) or `outcome_none()` (message, file type and status for the summary). `retrieve_row()` writes the file (with a unique name, see Gotchas), builds the summary rows (`manifest_row()`, once per polygon the reference polygon via `export_reference_polygon()`) and turns any error into a "Failed: ..." row. To add a dataset: write a `retrieve_<name>()` and add it to `retrieve_dataset()`.
4. **Constants** (`constants.R`): dataset menu and tab layout, dataset descriptions, STAC collection IDs, SNL settings, `adc_datasets`, the earliest data of each source (`weather_min_date`, `ndvi_min_month`, `fields_min_year`, checked in `test-live.R`), `availability_collections()` and the defaults of the rasters taken lazily with `delayedAssign()` from the functions that rNDC exports (`ndc_landuse_collection`, `landuse_default_year`, `nitrogen_layer_choices`).
5. **STAC/ADC helpers** (`stac_helpers.R`): `get_nitrogen_years()` / `get_landuse_years()` (`rNDC::ndc_nitrogen_years()` / `ndc_landuse_years()`, cached, with a fallback, via `get_raster_years()`), `count_items()` / `items_in_area()` (number of STAC items intersecting an area, via `rNDC::ndc_count()`; used for the "data available for the selected area" hint for Land Use and Nitrogen) and the process-level cache (`cache_get()`, `cache_set()`, TTL `ndc_cache_ttl`).
6. **Project layers** (`projects.R`): the `lter` collection is fetched once per process and classified by `name` into 4 projects (`classify_lter`, `get_lter_data`); `snl` (~264k parcels) is fetched per map viewport (`fetch_snl_bbox`, zoom-gated, capped by `snl_fetch_limit`). NDVI statistics come from `ndvi-lter` / `ndvi-snl` (`fetch_ndvi_stats_monthly`, a wrapper that turns `rNDC::get_ndvi_stats()` into a status, chosen by `detect_ndvi_collection` from the polygon's source name, e.g. `Nestboxes_3`, `SNL parcel_12`, and filtered on the polygon's `ndc_id`).
7. **Background retrieval** (`async.R`, `jobs.R`, `retrieval_run.R`): retrieval is split into shiny-free functions that can run in another R process: `retrieve_overview()` (the loop over the rows) and `retrieve_and_package()` (plus the download summary, the folder and the zip; `pack = TRUE` wraps terra rasters/vectors, which are pointers and cannot be sent between processes; `unpack_result()` undoes it). `retrieve_and_save()` in `server_download()` is the synchronous wrapper (with `withProgress()`); `run_retrieval()` chooses: `async_enabled()` (option `rNDC.Shiny.async`, set by `setup_async()` from `ndc_app()`: `NDC_ASYNC`, default on when not `interactive()`) submits a job to the job manager, otherwise it calls `retrieve_and_save()`. The manager (`jobs.R`, `ndc_jobs()`: one per R process, shared by all sessions; `NDC_WORKERS` run at a time, `NDC_MAX_QUEUE` may wait) takes a *function name* of this package and plain arguments (`job_submit()`), starts one `callr::r_bg()` process per job (`start_job_process()`/`job_worker()`; in a `load_all()` package the worker runs `pkgload::load_all()` first) with its own folder as `TMPDIR`, and keeps the state of each job: queued, running, done, failed or cancelled. It does not run by itself: `job_tick()` starts waiting jobs and notices finished ones, and is called every 0.5 s by `watch_job()` (`async.R`) of each session with a job, which also shows the queue position or the progress (a file written by `progress_writer()` in the worker, read by `read_progress()`) in a progress bar and calls `on_done`/`on_failed`/`on_cancelled`. `job_cancel()` removes a waiting job, or kills a running one (`kill_tree()`) and deletes its folder and files; "Cancel retrieval" (`input$cancel_retrieval`) and a session that ends use it (`session$onSessionEnded()`; a job that was done already goes to `on_abandoned` instead). `job_collect()` takes the outcome and forgets the job. A session has one retrieval at a time (`state$retrieving`, `state$job_id`). `ndc_gui()` and the app's `onStop` shut the manager down.
8. **Request cost and progress** (`request_cost.R`, no Shiny dependencies besides `setProgress`): `estimate_row_seconds()` estimates how long an overview row takes (Weather: one request per `weather_chunk_days` days; NDVI rasters: one download per day; everything else counts as quick). `server_dataset()` sums it over the overview when a dataset is added: above `warn_request_seconds` it warns, above `max_request_seconds()` (option `rNDC.Shiny.max_request_seconds`, environment variable `NDC_MAX_REQUEST_SECONDS`; default 300, or 900 in the background mode) it refuses. The timings in `request_seconds` were measured on a normal connection. While retrieving, `with_request_progress()` uses `rNDC::ndc_with_progress()`: the rNDC functions with many requests report `(message, current, total)` before each one (option `rNDC.progress`), and that becomes progress detail and bar position through `report_progress()`. (rNDC can also stop them with `rNDC.interrupt`; the app does not need it, since cancelling kills the worker process.)
9. **Polygons** (`polygons.R`): WKT columns, sequential source names, conversion of drawn/uploaded geometries (zip/gpkg/shp/geojson/kml); everything is kept in EPSG:4326 with a `wkt` column used by the retrieval code.

Dataset -> rNDC function:

| Dataset | Function |
|---|---|
| Agricultural fields, Soil map, AHN | `adc_url()` + `adc_get()` (AgroDataCube REST) |
| Weather | `get_closest_meteostation()`, `get_meteo_for_date()`, `get_meteo_for_long_period()` |
| NDVI (Geodata) | `download_avg_ndvi_month()`, `download_avg_ndvi_stack()` (GroenMonitor WCS) |
| NDVI (Statistics) | `ndc_get()` on `ndvi-lter` / `ndvi-snl` |
| Land Use | `get_landuse_raster()` (collection `lgn`) |
| Nitrogen | `get_nitrogen_raster()` (collections `ntot`, `nox`, `nh3`) |

The rNDC endpoint is `rNDC::ndc_endpoint()` (default: the test server `ndc-test.containers.wur.nl`; override with `options(rNDC.endpoint = ...)`).

Tests (`tests/testthat/`): `test-helpers.R` (pure helpers), `test-stac_helpers.R` and `test-projects.R` (stubbed HTTP; the paging and the statistics themselves are tested in rNDC), `test-retrieval-functions.R` (the functions of `retrieval.R`, directly), `test-availability.R`, `test-request-cost.R` (estimates, limits, progress), `test-async.R` (the job manager with a fake process `fake_manager()`, real `callr` processes, the app with `local_jobs()` and `settle()` (time passes with `session$elapse()`), and a fresh process when the package is installed; `setup.R` turns the mode off for all other tests), and the server logic with `shiny::testServer(app_server, ...)` in `test-app.R`, `test-retrieval.R`, `test-map.R` (clicks, drawing), `test-upload.R`, `test-projects-server.R` (LTER and SNL, with `session$elapse()` for the debounce) and `test-overview.R` (overview table, download flow); rNDC functions that download files are replaced with `local_mocked_bindings(..., .package = "rNDC")`; `test-live.R` (opt-in). `with_server()` in `helper-fixtures.R` runs code in the server after the first flush; the test's objects are copied into it, so record what a mock was called with in an environment (`rec$calls <- ...`) instead of reassigning a variable with `<<-`.

## Gotchas

- The rNDC raster functions (`get_landuse_raster`, `get_nitrogen_raster`) **stop with an error** when nothing matches instead of returning `NULL`; the real message arrives via the generic error handler of `retrieve_and_save()`. Their results are lists: use `$stack`.
- `rNDC::ndc_get(mode = "sf")` converts only the first page of results (and warns if incomplete); use `all_pages = TRUE` when all items are needed (as `fetch_lter_classified()` does). AgroDataCube Fields/Soiltypes are paged (default 50 features, `page_offset` is the page number): use `rNDC::adc_get_all()`.
- NDVI statistics queries return all NDVI features that intersect the polygon (neighbouring SNL parcels too); the results are filtered on the polygon's `ndc_id`. Drawn and uploaded polygons have none (and no NDVI statistics).
- `rNDC::ndc_trange()` formats a date as midnight UTC; the app extends the end of an NDVI period to 23:59:59.
- `rNDC::get_closest_meteostation()` returns `closest_id = character(0)` (not `NULL`) when no station id is found. Weather observations have `"geometry": null` in the API response.
- One R process serves all Shiny sessions: avoid `setwd()` and shared fixed paths in `tempdir()`; the cache and `Sys.getenv()` tokens are process-wide. `app_server()` reads the tokens when a session starts.
- Without the background mode a retrieval keeps the whole R process busy: that is why long ones are limited (see 8). In the background mode it holds nobody up, but occupies a worker (`NDC_WORKERS`); more wait in the queue.
- Things sent to a background process must be plain data and the *name* of a function of the package (a closure or the session would not survive, and the worker loads the package itself); `job_worker()` has no environment of its own and may only use base R and the package. Callbacks run when the user has maybe left: no reactive values after `session$onSessionEnded()`, and `showNotification()` from a callback needs `session = session`. The pipes of `callr` are not used (an unread pipe blocks a worker): output goes to files in the job folder.
- Uploads: Shiny's limit of 5 MB is raised to 100 MB in `ndc_setup()` (`NDC_MAX_UPLOAD_MB`, or an option that was set already), and the page says what it is.
- Date and year limits of the inputs are constants (`weather_min_date`, `ndvi_min_month`, `fields_min_year`): Weather has data from 1970 for the station tested (earlier requests give "no data"), NDVI from 2017-05-26, AgroDataCube fields from 2009. The Land Use years come from STAC (only 2024 at the moment).
- CI uses the newest R and packages (e.g. R 4.6, Shiny 1.14), which can be newer than the development environment (R 4.3, Shiny 1.11). Newer Shiny refuses access to the reactive values of a closed session ("its module session has been destroyed"): callbacks that run after the user has left (callbacks of background retrievals) must check `session$isClosed()` and not touch them (see `run_retrieval()`: `on_abandoned`), and tests must not read them after `session$close()`. To test against the versions of CI, install them in a separate library and put it first (`R_LIBS=<lib> Rscript -e 'devtools::test()'`).
- In `testServer()` tests, set the inputs (the first `session$setInputs()` flushes the initial observers, which reset the polygon selection) **before** setting `selected_polygons()`, and call `session$flushReact()` after setting a reactiveVal.
- `months()` on a number needs lubridate's method: the `lubridate` import in `R/rNDC.Shiny-package.R` makes sure it is registered.
- R code must be ASCII (non-ASCII is a warning in `R CMD check`): use `\u` escapes in strings. Files use LF line endings, as in rNDC.
- Column names used in dplyr/leaflet formulas are declared with `utils::globalVariables()` in `R/rNDC.Shiny-package.R`.
- "Vegetation structure" and "Ground water table" are shown in the menu as disabled "coming soon" entries.
- Output file names are built from dataset, view and polygon only, so `unique_export_file()` appends the period (`..._2023`), or a number, to a name that is already taken in the download folder (the first row keeps the plain name). `download_summary.csv` links each file to its period. The reference polygon (`<polygon>.gpkg`) is written once per polygon: `reference_polygon_file()` skips it when the file holds the same polygon, and numbers it (`<polygon>_2.gpkg`) when another polygon has the same name.
- The layers of `rNDC::ndc_sites()` (Nutnet, Nestkasten, Loobos, lampposts) are the same 34 polygons as the `lter` collection, so the app has no separate menu for them: the LTER projects are the study sites (and, unlike a copy from `ndc_sites()`, have an `ndc_id` for NDVI statistics). `test-live.R` checks that they still coincide.
- `CITATION.cff` lists the authors and version; update it together with `DESCRIPTION` when releasing.
- `aidecl.yaml` is the AI-usage declaration of the project (format of https://ai-declaration.org, as in rNDC); update it if the AI tools used or their role change.
