# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`rNDC.Shiny` (Apache-2.0, maintained for LTER-LIFE; the GitHub repository is `LTER-LIFE/rNDC-Shiny`) is an R package with a Shiny GUI to LTER-LIFE's **NatureDataCube**. It is built on the [`rNDC`](https://github.com/LTER-LIFE/rNDC) package, installed from GitHub (`Remotes: LTER-LIFE/rNDC` in `DESCRIPTION`, its `main` branch), version 0.5.1 or later (`Imports: rNDC (>= 0.5.1)`: `ndc_with_progress()`, `ndc_datasets(collections = )`, `stac_year_trange()`, `stac_availability()`, the exported defaults, `ndc_get(all_pages = TRUE)`, `adc_get_all()`, `ndc_ndvi_stats()` and the `ndc_*_years()` functions): prefer exported `rNDC::` functions over re-implementing requests here, and put generic helpers that other rNDC users would want in rNDC itself. Unqualified calls to imported packages must be listed as imports in `R/rNDC.Shiny-package.R` (`@import shiny`, specific `@importFrom` for the rest, to avoid masking); otherwise use `pkg::fn`. `DESCRIPTION` `Imports` lists the packages.

## Commands

Run R through the conda env: `conda run -n base_r Rscript -e '...'`. It has all dependencies, `devtools`, `roxygen2` and `webmockr`, and `rNDC` installed from `LTER-LIFE/rNDC`. Credentials for live runs are in `~/.Renviron`.

- Load during development: `devtools::load_all()`. Run the app: `NDC_TOKEN=... conda run -n base_r Rscript -e 'devtools::load_all(); ndc_gui(port = 3838, launch.browser = FALSE)'` (only `NDC_TOKEN` is required; dummy values are enough to check that the app starts and serves, but data requests then fail).
- Run all tests: `devtools::test()`; a single file: `devtools::test(filter = "retrieval")` (matches `tests/testthat/test-<filter>.R`). The tests are offline: HTTP is stubbed at transport level with `webmockr` (httr adapter; rstac and httr both go through httr). `tests/testthat/helper-fixtures.R` has `local_stac_api()` (stub STAC API at `https://example.org/api/`, with result pages and an optional error status), `adc_re()` + `geojson_features()` for AgroDataCube stubs, `request_uris()` / `last_request_body()` to inspect the requests, and `selected_polygon()`.
- Regenerate docs and `NAMESPACE`: `roxygen2::roxygenise()`. `NAMESPACE` and `man/` are **generated**; never edit them by hand. Imports are declared as tags in `R/rNDC.Shiny-package.R`, and every exported function needs `@export` plus a roxygen block.
- Full check: `R CMD build .` in a scratch directory, then `R CMD check --no-manual rNDC.Shiny_*.tar.gz`. It must stay free of errors, warnings and notes (CI uses `error-on: "warning"`).
- Live API tests (`tests/testthat/test-live.R`) are skipped unless `RNDC_LIVE_TESTS=true` (plus both tokens): `RNDC_LIVE_TESTS=true conda run -n base_r Rscript -e 'devtools::test(filter = "live")'`.
- Update rNDC to the latest release: `conda run -n base_r Rscript -e 'remotes::install_github("LTER-LIFE/rNDC", upgrade = "never")'` (add `ref = "v0.5.2"` for a tag). Check `packageDescription("rNDC")$RemoteSha` when behaviour differs from what the rNDC source says.
- Container: `docker compose up --build` (or `podman compose`), reading `.env` (copy `.env.example`). The image installs rNDC from GitHub (`RNDC_REF`, default the tag of the rNDC release, `v0.5.2`; the image is named `rndc-shiny:<version of the app>` in `compose.yaml` and has the labels `org.opencontainers.image.version` and `nl.lter-life.rndc.ref`: update them together with `RNDC_REF` and `DESCRIPTION`), the other dependencies from `DESCRIPTION` (`remotes::install_deps()`, incl. `Remotes:`), then this package, and runs `rNDC.Shiny::ndc_gui(host = '0.0.0.0', port = 3838)`; the app is served at `http://localhost:3838/` (`SHINY_APP_BASE_URL` does not create a route, it only sets Shiny's `appBaseUrl` behind a reverse proxy). Docker is not available in the dev environment: the image is built by the `docker-build` workflow only. The build can use a GitHub token against the rate limit of the GitHub API (not kept in the image): `docker build --secret id=github_pat,env=GITHUB_PAT .`. The `docker-build` workflow builds the image with `GITHUB_TOKEN`, loads the package in it, runs a job in a fresh background process of the image, starts the container and checks that the page and the logo are served.
- CI (`.github/workflows/`): `R-CMD-check.yaml` runs the offline check on push/PR; `live-checks.yaml` runs the live tests weekly (default branch) or on manual dispatch, using the `NDC_TOKEN`/`ADC_TOKEN` repository secrets; `docker-build.yaml` builds the image (no push) when the Docker files or the package change. Repo: https://github.com/LTER-LIFE/rNDC-Shiny.
- Credentials come from env vars: `NDC_TOKEN` (NatureDataCube STAC API, also the default `token` of `rNDC::ndc_get()`, land use and nitrogen functions; **required**) and `ADC_TOKEN` (AgroDataCube: Fields and Weather only, the datasets that the NatureDataCube does not have; **optional**, those two are disabled without it; `adc_datasets`). Never write tokens to the repo or to outputs.

## Architecture

Code lives in flat `R/*.R` files (R allows no subfolders), arranged like rNDC: the file name starts with the layer that the code belongs to, so related files sort together; several small related functions share a file, a long one has its own. Function names start with the layer too, and the test file has the name of the R file that it tests (`test-job_manager.R` for `job_manager.R`; the shared fixtures are in `helper-fixtures.R`):

- `ndc_*.R`, `app_*.R`, `server_*.R`: the launchers (the only exports), the page, and one server function per area of the page; `state.R` (the shared state) and `map_helpers.R` (functions of the map that several areas share).
- `retrieve_*.R`: retrieving the overview (`retrieve_dataset`, `retrieve_row`, `retrieve_overview`) and its cost and progress (`retrieve_cost`); `export_*.R`: what the retrieval writes (`export_files`, `export_references`).
- `job_*.R`: the background processes (`job_setup`, `job_manager`, `job_process`: the worker, how it is started and the progress file).
- `polygon_*.R` (`polygon_utils`: helpers and limits, `polygon_upload`), `adc_geometry.R`, `project_*.R` (`project_layers`: LTER, SNL and the NDVI statistics), `availability.R`, `catalogue.R`: the areas of interest and what is known about them.
- `cache.R`, `stac_lookups.R`: lookups with a cache; `constants.R`: settings and the dataset menu; `utils.R`: what everything shares (`env_count()`, `same_na()`, `safe_filename()`); `rNDC.Shiny-package.R` has the imports.

By layer:

1. **Launchers** (`ndc_gui.R`, `ndc_app.R`, the only exports): `ndc_gui()` runs `shiny::runApp(ndc_app(), ...)` and returns what `stopApp()` is given (the "Return data to R" button, shown only when `interactive()`); `ndc_app()` registers the `ndc-www` resource path (logo, from `inst/app/www`) and returns `shinyApp(app_ui(), app_server)`. `ndc_setup()` (internal, called by `ndc_app()`) stops without `NDC_TOKEN`, warns without `ADC_TOKEN` and sets `shiny.appBaseUrl` from `SHINY_APP_BASE_URL`. `inst/app/app.R` is a one-line entry point (`rNDC.Shiny::ndc_app()`) for Shiny Server.
2. **UI and server** (`app_ui.R`, `app_server.R`, `server_*.R`): `app_ui()` returns the page (CSS/JS inline, with plain input ids: no module namespaces). `app_server()` creates the shared `state` (`state_create()` in `state.R`: the reactiveVals for the drawn/selected/project/uploaded polygons, the `overview`, the download messages and the tokens) and the map `helpers` (`map_helpers_create()`: `update_selected_highlights()`, `clear_map_polygons()`, ...), and calls one function per area, each registering its observers and outputs and unpacking the state it needs at its top: `server_availability()` (which datasets have data for the selected area, see 5), `server_dataset()` (dataset settings, adding to the overview; returns `build_controls_for()`), `server_projects()` (LTER/SNL layers), `server_map()` (clicks, drawing), `server_upload()`, `server_overview()`, `server_download()` (returns `retrieve_and_save()`) and `server_help()`. `app_server()` also keeps the state and those two functions by name in its own environment, which is how the tests reach them. The `overview` reactiveVal is the "shopping cart" (one row per dataset x polygon x year/dates, with the polygon `sf` in a list column). `retrieve_and_save()` loops over the rows with `retrieve_row()` (see 3), collects the data, the `download_summary.csv` manifest and the messages, writes the manifest into a unique temp folder, zips it with `export_zip()` and removes the folder. It backs both "Download" (zip) and "Return data to R" (`stopApp(list(datasets, overview, messages, summary, ...))`); per-dataset messages ("Retrieved: ...", "Failed: ... - reason") are shown in the messages panel. To add a piece of server logic, put it in the `server_*.R` of its area (or a new one, called from `app_server()`); share state through `state`, and functions used by several areas through `helpers`.
3. **Retrieval** (`retrieve_dataset.R`, `retrieve_row.R`, `retrieve_overview.R`, `export_files.R`, no Shiny dependencies): `retrieve_row(row, index, workdir, ndc_token, adc_token)` handles one overview row. `retrieve_dataset()` dispatches to one function per dataset (`retrieve_agricultural_fields()`, `retrieve_weather()`, `retrieve_nitrogen()`, `retrieve_ndvi_rasters()`, ...), each returning an *outcome*: `retrieve_outcome_data()` (the data, its name, file extension, messages and optional writer) or `retrieve_outcome_none()` (message, file type and status for the summary). `retrieve_row()` writes the file (with a unique name, see Gotchas), builds the summary rows (`export_manifest_row()`, once per polygon the reference polygon via `export_reference_polygon()`) and turns any error into a "Failed: ..." row. To add a dataset: write a `retrieve_<name>()` and add it to `retrieve_dataset()`.
4. **Constants** (`constants.R`): dataset menu and tab layout, dataset descriptions, STAC collection IDs, SNL settings, `adc_datasets`, the earliest data of each source (`weather_min_date`, `ndvi_min_month`, `fields_min_year`, checked in `test-live.R`), the defaults of the rasters taken lazily with `delayedAssign()` from the functions that rNDC exports (`ndc_landuse_collection`, `landuse_default_year`, `nitrogen_layer_choices`).
5. **Catalogue for the area** (`catalogue.R`, `server_catalogue.R`): the dialog of `rNDC::ndc_available()` for the selected polygons (optional period), cached per area and period; the table is built by the shiny-free `catalogue_display()`, and its text is escaped (it comes from services). The first dates of the AgroDataCube/GroenMonitor datasets (`weather_min_date`, `ndvi_min_month`, `fields_min_year` in `constants.R`) come from `rNDC::ndc_external_datasets()`: do not write them here again.
6. **STAC/ADC helpers and availability** (`cache.R`, `stac_lookups.R`, `availability.R`, `server_availability.R`; the checks are made on demand, never while areas are selected: when the **Check data availability** button (below the map) is clicked, for all datasets, with the marks and the sentence staying until the next check or until the selection of polygons, a year or date input (the `settings` reactive: only a new value of an input that had one counts, not an input appearing with its dataset) or the Weather distance changes (then `server_availability()` clears them without checking anything and, if there were marks, shows a `warning` notification to check again), and when a dataset is added, by `helpers$availability$check_added()` for that dataset and each polygon: a polygon with status `no` is not added, with an error naming it, and a check that returns NULL (a failure, 20 s limit per request through `httr::with_config()`) lets it through; the same click opens the dialog of `server_catalogue.R`): `stac_nitrogen_years()` / `stac_landuse_years()` (`rNDC::ndc_nitrogen_years()` / `ndc_landuse_years()`, cached, with a fallback, via `stac_raster_years()`), `stac_count_items()` (number of STAC items in an area, via `rNDC::ndc_count()`), `rNDC::stac_availability()` (ONE STAC search over the Land Use and nitrogen collections: a table of collection x year, with the collections that a full page may have hidden asked one by one; it lives in rNDC, which has to be newer than 0.5.1 for it) and the process-level cache (`cache_get()`, `cache_set()`, `cache_key()`: a long key, e.g. a WKT, is hashed because names in an environment are limited to 10000 bytes; TTL `ndc_cache_ttl`, at most `ndc_cache_max_entries`). `availability_check(area, ndc_token, adc_token, years, weather_max_km, datasets, view)` (shiny-free; only the requests of the `datasets` asked for are made, `view` is the NDVI view) returns one row per dataset with a `status` (`yes`, `partial`, `no`, `unknown`, `na`) and a `detail` sentence: Land Use and Nitrogen from `stac_availability()`, Soil map / AHN / Agricultural fields by an AgroDataCube request for one feature (AHN answers with one feature anywhere: its properties must not be empty; the polygon is shortened like in a retrieval), Weather by the distance to the closest station (the box `input$weather_max_km` of the Weather settings, default `weather_max_station_km` = 30; kept in `state$weather_max_km`, so that it survives the settings being rebuilt; a bad value is ignored; it only affects the check, not which station a retrieval uses), NDVI rasters by the outline of the Netherlands bundled with rNDC (`nl.gpkg`) and NDVI statistics by project-area names. Parts are cached per area (Fields per year; the year of a raster needs no new request), a failed request is `unknown` and never cached. `server_availability()` runs it debounced on the union of the selected polygons (and again when a year changes), keeps the table in `state$availability`, marks the dataset menu through the `ndc_availability` message (checked in a fake DOM with node when it changed) and fills `output$availability` for the selected dataset; `server_dataset()` warns, but adds, a dataset whose status is `no`.
7. **Project layers** (`project_layers.R`): the `lter` collection is fetched once per process and classified by `name` into 4 projects (`project_lter_classify`, `project_lter_data`); `snl` (~264k parcels) is fetched per map viewport (`project_snl_fetch`, zoom-gated, capped by `snl_fetch_limit`). NDVI statistics come from `ndvi-lter` / `ndvi-snl` (`project_ndvi_stats`, a wrapper that turns `rNDC::ndc_ndvi_stats()` into a status, chosen by `project_ndvi_collection` from the polygon's source name, e.g. `Nestboxes_3`, `SNL parcel_12`, and filtered on the polygon's `ndc_id`).
8. **Background retrieval** (`job_setup.R`, `job_manager.R`, `job_process.R`, `retrieve_overview.R`): retrieval is split into shiny-free functions that can run in another R process: `retrieve_overview()` (the loop over the rows) and `retrieve_and_package()` (plus the download summary, the folder and the zip, the parameters of the retrievals (`retrieve_row()` gives each rNDC function a hidden `.params_<row>_<slot>.json` path as `save_params` (`retrieve_params_path()`); `export_place_parameters()` moves the files to `parameters/<data file name>.json` (Weather: also `_station`), or `export_read_parameters()` returns their texts when nothing is written; the zip is made with `mode = "mirror"` to keep the folder), and the references: `export_references.R` maps the datasets to STAC collections (`export_dataset_collections()`), reads their metadata once with `rNDC::ndc_metadata()` and fills `reference`/`license` of the summary (`export_add_references()`) and writes `CITATIONS.txt` (`export_citations_text()`); a failure to read it only adds a message; `pack = TRUE` wraps terra rasters/vectors, which are pointers and cannot be sent between processes; `retrieve_unpack()` undoes it). `retrieve_and_save()` in `server_download()` is the synchronous wrapper (with `withProgress()`); `run_retrieval()` chooses: `job_async_enabled()` (option `rNDC.Shiny.async`, set by `job_setup_async()` from `ndc_app()`: `NDC_ASYNC`, default on when not `interactive()`) submits a job to the job manager, otherwise it calls `retrieve_and_save()`. The manager (`jobs.R`, `ndc_jobs()`: one per R process, shared by all sessions; `NDC_WORKERS` run at a time, `NDC_MAX_QUEUE` may wait) takes a *function name* of this package and plain arguments (`job_submit()`), starts one `callr::r_bg()` process per job (`job_start_process()`/`job_worker()`; in a `load_all()` package the worker runs `pkgload::load_all()` first) with its own folder as `TMPDIR`, and keeps the state of each job: queued, running, done, failed or cancelled. It does not run by itself: `job_tick()` starts waiting jobs and notices finished ones, and is called every 0.5 s by `download_watch_job()` (`async.R`) of each session with a job, which also shows the queue position or the progress (a file written by `job_progress_writer()` in the worker, read by `job_progress_read()`) in a progress bar and calls `on_done`/`on_failed`/`on_cancelled`. `job_cancel()` removes a waiting job, or kills a running one (`kill_tree()`) and deletes its folder and files; "Cancel retrieval" (`input$cancel_retrieval`) and a session that ends use it (`session$onSessionEnded()`; a job that was done already goes to `on_abandoned` instead). `job_collect()` takes the outcome and forgets the job. A session has one retrieval at a time (`state$retrieving`, `state$job_id`). `ndc_gui()` and the app's `onStop` shut the manager down.
9. **Request cost and progress** (`retrieve_cost.R`, no Shiny dependencies besides `setProgress`): `retrieve_estimate_seconds()` estimates how long an overview row takes (Weather: one request per `weather_chunk_days` days; NDVI rasters: one download per day; everything else counts as quick). `server_dataset()` sums it over the overview when a dataset is added: above `warn_request_seconds` it warns, above `max_request_seconds()` (option `rNDC.Shiny.max_request_seconds`, environment variable `NDC_MAX_REQUEST_SECONDS`; default 300, or 900 in the background mode) it refuses. The timings in `request_seconds` were measured on a normal connection. While retrieving, `retrieve_with_progress()` uses `rNDC::ndc_with_progress()`: the rNDC functions with many requests report `(message, current, total)` before each one (option `rNDC.progress`), and that becomes progress detail and bar position through `retrieve_report_progress()`. (rNDC can also stop them with `rNDC.interrupt`; the app does not need it, since cancelling kills the worker process.)
10. **Polygons** (`polygon_utils.R`, `polygon_upload.R`, `adc_geometry.R`): WKT columns, sequential source names, conversion of drawn/uploaded geometries (zip/gpkg/shp/geojson/kml); everything is kept in EPSG:4326 with a `wkt` column used by the retrieval code. Uploaded features each get a `layer_id` (the shape on the map, `polygon_number_uploaded()`) and share an `upload_id` (the entry in the list of uploads, what "Remove" takes away). `polygon_clean()` turns what users bring (uploads, drawings) into valid EPSG:4326 polygons: only (multi)polygons, no Z, an assumed CRS when it is missing or "undefined" (`polygon_crs_missing()`), and repair of invalid ones **in the Dutch grid (EPSG:28992)**, because `sf` works on the sphere for lon/lat (s2) and its `st_make_valid()` gives a wrong, still invalid result there; what it did is in the `notes` attribute (`polygon_notes()`). `polygon_process_upload()` checks zips (`polygon_zip_problem()`: file count, unpacked size, paths outside the archive), unpacks into `polygon_upload_dir()` folders that it removes, except those of a GeoPackage that waits for a layer (`kept_dirs`, removed by `server_upload()` at session end). `polygon_utils.R` also has the limits on user polygons: the area limit (`max_area_km2()`, `NDC_MAX_AREA_KM2`, checked in `server_dataset()` when a dataset is added, Weather excepted), the number of features per upload (`max_upload_features`) and `adc_geometry()`, which shortens the polygon for AgroDataCube requests (its URLs fail above ~8000 characters; `adc_max_wkt_chars`).

Dataset -> rNDC function:

| Dataset | Function |
|---|---|
| Agricultural fields | `adc_url()` + `adc_get_all()` (AgroDataCube REST) |
| AHN (Statistics / Geodata) | `ndc_ahn_stats()` / `ndc_ahn_raster()` (collection `ahnmetrics`: terrain height and object height, different grids, so one file each) |
| Soil map | `ndc_soil_raster()` (collection `soiltypes`: codes; the legend comes as a second file) |

A dataset that comes as several files returns an outcome with `extras` (`retrieve_outcome_data()`; `retrieve_with_extras()`): `retrieve_row()` writes each as `<base>_<suffix>.<ext>` with its own manifest row (the parameters file belongs to the first), and without files returns the others in `more` (named `<name>_<index>`), which `retrieve_overview()` adds to the results.
| Weather | `adc_weather_station()`, `adc_weather_date()`, `adc_weather_long_period()` |
| NDVI (Geodata) | `ndc_ndvi_month()`, `ndc_ndvi_stack()` (the `ndvi` collection of the NatureDataCube: the daily GroenMonitor rasters) |
| NDVI (Statistics) | `ndc_get()` on `ndvi-lter` / `ndvi-snl` |
| Land Use | `ndc_landuse_raster()` (collection `lgn`) |
| Nitrogen | `ndc_nitrogen_raster()` (collections `ntot`, `nox`, `nh3`) |

The rNDC endpoint is `rNDC::ndc_endpoint()` (default: the test server `ndc-test.containers.wur.nl`; override with `options(rNDC.endpoint = ...)`).

Tests (`tests/testthat/`): one file per R file, named after it (`test-<file>.R`), as in rNDC. Offline: `test-job_manager.R` (the job manager with a fake process `fake_manager()`), `test-job_process.R` (the progress file, real `callr` processes, and a fresh process when the package is installed; `setup.R` turns the background mode off for all other tests), `test-job_setup.R`, `test-retrieve_dataset.R`, `test-retrieve_row.R`, `test-retrieve_overview.R`, `test-retrieve_cost.R` (also the progress), `test-export_files.R` (the parameters files, the summary and the zip), `test-export_references.R`, `test-polygon_utils.R` (also the limits), `test-polygon_upload.R`, `test-adc_geometry.R`, `test-project_layers.R` (also the NDVI statistics; stubbed HTTP; the paging and the statistics themselves are tested in rNDC), `test-cache.R`, `test-stac_lookups.R`, `test-constants.R`, `test-utils.R`, `test-availability.R` (the check per dataset with mocked services, and the app), `test-catalogue.R`, and the server logic with `shiny::testServer(app_server, ...)` in `test-ndc_app.R`, `test-server_dataset.R`, `test-server_map.R` (clicks, drawing), `test-server_upload.R`, `test-server_projects.R` (LTER and SNL, with `session$elapse()` for the debounce), `test-server_overview.R` and `test-server_download.R` (the retrieval, the download buttons, and the background retrieval with `local_jobs()` and `settle()`: time passes with `session$elapse()`); rNDC functions that download files are replaced with `local_mocked_bindings(..., .package = "rNDC")`; `test-live.R` (opt-in). A helper defined in a test file (such as `date <- as.Date`) is not visible to the others: put what several files need in `helper-fixtures.R` (a helper named like a base function, such as `date`, must stay in the test file, where it takes precedence). `with_server()` in `helper-fixtures.R` runs code in the server after the first flush; the test's objects are copied into it, so record what a mock was called with in an environment (`rec$calls <- ...`) instead of reassigning a variable with `<<-`.

## Gotchas

- The rNDC raster functions (`ndc_landuse_raster`, `ndc_nitrogen_raster`) **stop with an error** when nothing matches instead of returning `NULL`; the real message arrives via the generic error handler of `retrieve_and_save()`. Their results are lists: use `$stack`.
- `rNDC::ndc_get(mode = "sf")` converts only the first page of results (and warns if incomplete); use `all_pages = TRUE` when all items are needed (as `project_lter_fetch()` does). AgroDataCube Fields/Soiltypes are paged (default 50 features, `page_offset` is the page number): use `rNDC::adc_get_all()`.
- NDVI statistics queries return all NDVI features that intersect the polygon (neighbouring SNL parcels too); the results are filtered on the polygon's `ndc_id`. Drawn and uploaded polygons have none (and no NDVI statistics).
- `rNDC::ndc_trange()` formats a date as midnight UTC; the app extends the end of an NDVI period to 23:59:59.
- `rNDC::adc_weather_station()` returns `closest_id = character(0)` (not `NULL`) when no station id is found. Weather observations have `"geometry": null` in the API response.
- One R process serves all Shiny sessions: avoid `setwd()` and shared fixed paths in `tempdir()`; the cache and `Sys.getenv()` tokens are process-wide. `app_server()` reads the tokens when a session starts.
- Without the background mode a retrieval keeps the whole R process busy: that is why long ones are limited (see 8). In the background mode it holds nobody up, but occupies a worker (`NDC_WORKERS`); more wait in the queue.
- Things sent to a background process must be plain data and the *name* of a function of the package (a closure or the session would not survive, and the worker loads the package itself); `job_worker()` has no environment of its own and may only use base R and the package. Callbacks run when the user has maybe left: no reactive values after `session$onSessionEnded()`, and `showNotification()` from a callback needs `session = session`. The pipes of `callr` are not used (an unread pipe blocks a worker): output goes to files in the job folder.
- Uploads: Shiny's limit of 5 MB is raised to 100 MB in `ndc_setup()` (`NDC_MAX_UPLOAD_MB`, or an option that was set already), and the page says what it is.
- Date and year limits of the inputs are constants (`weather_min_date`, `ndvi_min_month`, `fields_min_year`): Weather has data from 1970 for the station tested (earlier requests give "no data"), NDVI from 2017-05-26, AgroDataCube fields from 2009. The Land Use years come from STAC (only 2024 at the moment).
- CI uses the newest R and packages (e.g. R 4.6, Shiny 1.14), which can be newer than the development environment (R 4.3, Shiny 1.11). Newer Shiny refuses access to the reactive values of a closed session ("its module session has been destroyed"): callbacks that run after the user has left (callbacks of background retrievals) must check `session$isClosed()` and not touch them (see `run_retrieval()`: `on_abandoned`), and tests must not read them after `session$close()`. To test against the versions of CI, install them in a separate library and put it first (`R_LIBS=<lib> Rscript -e 'devtools::test()'`).
- In `testServer()` tests, set the inputs (the first `session$setInputs()` flushes the initial observers, which reset the polygon selection) **before** setting `selected_polygons()`, and call `session$flushReact()` after setting a reactiveVal.
- `months()` on a number needs lubridate's method: the `lubridate` import in `R/rNDC.Shiny-package.R` makes sure it is registered.
- R code must be ASCII (non-ASCII is a warning in `R CMD check`): use `\u` escapes in strings. Files use LF line endings, as in rNDC.
- Column names used in dplyr/leaflet formulas are declared with `utils::globalVariables()` in `R/rNDC.Shiny-package.R`.
- "Vegetation structure" and "Ground water table" are shown in the menu as disabled "coming soon" entries.
- Output file names are built from dataset, view and polygon only, so `export_unique_file()` appends the period (`..._2023`), or a number, to a name that is already taken in the download folder (the first row keeps the plain name). `download_summary.csv` links each file to its period. The reference polygon (`<polygon>.gpkg`) is written once per polygon: `export_polygon_file()` skips it when the file holds the same polygon, and numbers it (`<polygon>_2.gpkg`) when another polygon has the same name.
- The layers of `rNDC::ndc_sites()` (Nutnet, Nestkasten, Loobos, lampposts) are the same 34 polygons as the `lter` collection, so the app has no separate menu for them: the LTER projects are the study sites (and, unlike a copy from `ndc_sites()`, have an `ndc_id` for NDVI statistics). `test-live.R` checks that they still coincide.
- `CITATION.cff` lists the authors, the version and the release date; update it together with `DESCRIPTION` (`Version`, `Date`), the heading of `NEWS.md`, and the example tag in the `Dockerfile` comment when releasing. `RNDC_REF` (Dockerfile, `compose.yaml`) is the tag of the rNDC release that the image installs.
- `aidecl.yaml` is the AI-usage declaration of the project (format of https://ai-declaration.org, as in rNDC); update it if the AI tools used or their role change.
